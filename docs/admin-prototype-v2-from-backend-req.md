> **依据**：《后端需求.docx》（运营后台功能全文）  
> **对照**：现有仓库管理后台线框 `src/data/screens-*.ts`（B01–B27，共 22 屏）+ 侧栏 IA `AdminWireframe.tsx` + 决策 `decisions.ts`（H-01…H-12）  
> **关联**：移动端线框 `src/data/mobile/*`（S01–S31）与决策 B-01…B-13  
> **日期**：2026-08-07  
> **用途**：差异分析 + **对齐后端需求后的新原型规格**（可直接拆线框 / 排期 / 评审）  
> **落地状态**：**已写入代码**（`src/data/screens-v2-p0.ts`、侧栏 `AdminWireframe.tsx`、决策 H-02/H-13/H-14、总览页）。冲突以后端需求为准。

## 0. 结论摘要

| 维度 | 结论 |
|---|---|
| 现有后台原型覆盖度 | **约 35%～40%** 功能面（偏「内容供给 + 评测排课 + 用户/迁移 + 订阅流水」） |
| 后端需求完整度 | **10 大业务域 + 跨模块关系 + 公共能力**，明显大于当前线框 |
| 最大缺口 | **运营总览、用户标签/分群、触达任务效果、课程组合、打卡/积分规则、社区全链路、会员套餐与退款对账、商城履约、基础运营配置** |
| 次要缺口 | 用户档案深度、问卷周期复评、消息发送记录、客服企微 |
| 口径冲突（必须先统一） | ① 课表 **28 天 vs 30 天滚动** ② **积分 vs 能量值** 命名 ③ 试用时长与漏斗定义 ④ 商城/社区是否进 MVP |
| 本 v2 策略 | **按后端需求重建 IA 与屏幕清单**；保留已有 B 编号能力，**缺口用新编号扩展**；分 P0 / P1 / P2 落地 |

`待审 → 通过 | 拒绝 | 要求修改 | 转人工`。
