# APP 开发规划

## 1. 建设目标

APP V1 要把复杂的长期档案和规则引擎隐藏在轻量、可控、可解释的体验后面：用户完成一次 Onboarding 得到稳定的 30 天计划，每天只回答一个问题；系统在不放宽安全限制的前提下，仅对必要范围做调整，并让用户知道为什么。

当前原型的五 Tab、Today 卡片、Check-in 两步确认、日历和课程播放骨架可以复用。开发重点是纠正状态边界、替换旧问卷和枚举、增加档案/解释/异常状态，而不是重新设计整个导航。

## 2. V1 导航与页面范围

建议保留底部导航：

```text
Today｜课程库｜日历｜社区（可选轻量版）｜我的
```

一级流程：

- 登录/注册/老用户迁移；
- 数据说明与 Onboarding；
- 档案摘要与 30 天计划生成；
- Today + 一问 Check-in + 状态确认；
- 课程详情、播放、投屏和反馈；
- 日历与 Re-plan 差异；
- 训练档案、周期事实、隐私与推荐记录。

社区、会员、积分和消息中心不应阻塞核心训练闭环。社区若保留，采用 PDF 建议的轻社交，不在 V1 引入评论。

## 3. 核心状态模型

### 3.1 长期档案与当天输入分离

```text
Onboarding / 用户明确修改
        ↓
User Training Profile（长期、版本化）
        ↓
30-day Plan

Daily Check-in（当天一次）
        ↓
Daily Adapt（仅今天）

周期实际事件 / 长期档案变化
        ↓
Re-plan（仅未来受影响日期）
```

客户端不能把 Daily Check-in 写回长期档案，也不能因经期事实自动将 `day_state` 设为 WARM。

### 3.2 状态值

- `PUSH`：默认保持原安排，不自动升级；
- `SOFT`：先降低负荷/冲击/跳跃，尽量保留训练意图，再使用备选；
- `WARM`：温和调整、换安全备选或休息；
- 周期上下文单独显示，不与上述状态合并；
- 页面使用服务端 reason code 映射文案，不在客户端重算规则。

### 3.3 页面加载状态

所有核心页至少支持：`loading / ready / empty / blocked / stale / offline / error`。Plan、Re-plan 是异步任务，还需 `queued / processing / partially_ready / failed`。

## 4. 页面改造

### 4.1 S03 欢迎与数据说明

保留品牌表达，CTA 调整为“用 3–5 分钟了解你的训练需要”。在进入敏感问题前说明：

- 收集信息用于制定和调整训练计划；
- 周期、生命周期和身体限制属于敏感信息；
- 产品不是医疗诊断或治疗建议；
- 用户可在“我的”查看、更正、导出或申请删除；
- V1 孕期不提供自动课程推荐。

老用户迁移不能默默用旧 12 题结果生成新档案，应显示需要补充的信息与原因。

### 4.2 S04 Onboarding

#### 结构

- 15 个主问题；
- 生命周期、安全限制和产后条件分支；
- 单题一屏或小组一屏；
- 显示进度但分支变化时不要出现倒退感；
- 每步自动保存，允许退出后继续；
- 自由文本尽量少，敏感字段说明就近展示。

#### 核心输入

- 年龄、身高、体重（BMI 仅内部参考，不对用户做价值判断）；
- 主/次目标；
- 当前频次、连续训练能力、跳跃耐受；
- 受限部位与严重程度；
- 可训练时长、目标频次；
- 喜欢/避开的训练形式；
- 生命周期及必要分支。

删除设备问题。Fitness Capacity 技术值只使用 L1–L5；UI 展示用户友好描述，不直接要求用户给自己评级。

#### 安全分支

- 用户选择 `PREGNANT` 时进入 V1 Block 页面，说明当前不提供自动排课，可修改误选答案；不继续收集无用途的孕期详细信息。
- 盆底/腹直肌等限制在课程安全字段未就绪时，同样显示无法自动匹配或转人工路径。
- 任何 Block 都不能以“随便推荐一个低强度课程”兜底。

### 4.3 S05/S06 档案摘要与计划生成

提交前展示简短摘要：主目标、能力、时长/频次、训练限制、生命周期；允许返回修改。

提交后：

- 创建 `User Training Profile` 版本；
- 异步生成 30 天 Plan；
- 页面显示真实进度阶段，而不是虚假百分比；
- 成功后展示计划概览；
- 无安全课程时显示明确原因和下一步；
- 网络中断后可通过 job id 恢复，不重复创建计划。

不生成冗长测评报告。

### 4.4 S08 日历/月计划

日历展示 30 天 Training Intent 和当日状态：

- 原计划、当前结果、完成/跳过状态；
- Today 调整标记与 Re-plan 标记区分；
- 点击某天查看 Primary + Backup A/B/C、调整原因和版本；
- Re-plan 后提供日期级差异：“哪些保持、哪些调整、哪些替换”；
- 已完成和过去日期保持不变。

文案删除“Check-in 会重排今天和未来”。正确表达是：每日状态只调整今天，周期事实或长期档案改变才可能更新未来安排。

### 4.5 S09 Today

建议卡片顺序：

1. 问候、日期和轻量周期上下文；
2. Check-in 未完成时的一问入口；
3. 今日状态及用户确认标记；
4. 今日课程、时长、意图与“为什么推荐”；
5. 饮食支持、轻仪式/冥想等内容；
6. 完成/反馈入口。

规则：

- Check-in 前显示原计划，不预判用户疲劳；
- “经期第 N 天”只作为上下文，不出现“所以是 Warm Day”；
- 状态和课程调整必须区分“系统建议”和“你已确认”；
- 当日调整被撤销或预览过期时，及时刷新；
- 如果无安全课程，允许休息并解释，不把空状态当系统错误。

### 4.6 S19 Check-in 与状态确认

流程：

```text
问题：今天感觉怎么样？
  ├─ Yes, I feel great
  ├─ Energy is low
  └─ I got my period
        ↓
服务端预览：建议状态 + 原因 + 课程变化
        ↓
用户确认建议状态，或手动改为 Push / Soft / Warm
        ↓
服务端确认：写入 Check-in，必要时调整今天
```

首 7 次显示简短机制说明，可逐次减少；说明可在“了解状态”重新打开。客户端记录 preview id/revision，确认时若返回 `PREVIEW_STALE`，重新预览而非直接提交旧结果。

“I got my period”会同时进入周期事实确认步骤：

- 先确认日期；
- 告知可能调整未来哪些日期；
- 由用户确认后触发 Re-plan；
- 今天仍按 Check-in 的建议/用户确认状态做 Adapt。

### 4.7 S20 当天调整

用服务端返回的动作表达层级：

- `KEEP`：保持原课程；
- `ADJUST`：同课程/同意图的低冲击或短时版本；
- `REPLACE`：从 Backup A/B/C 中选安全课程；
- `REST`：无合适课程或 WARM 状态下选择休息。

页面显示原安排与新安排、保留了什么、改变了什么、原因和撤销入口。SOFT 不得直接从核心力量跳到无关 Stretch，除非所有保留意图的候选均不安全/不可用，并在原因中说明。

### 4.8 S21 周期事实与 Re-plan

用户确认实际经期开始/结束后：

- 先保存事实，不覆盖历史预测；
- 展示未来受影响日期和预计变化数量；
- 异步完成 Re-plan 后显示 Keep/Adjust/Replace diff；
- 不改变过去/已完成日；
- 支持在允许窗口内纠正日期，生成 supersedes 记录和新计划版本。

Re-plan 与当天 Adapt 同时发生时，UI 可显示一个合并进度，但后端顺序固定为先处理未来 Re-plan，再对今天 Adapt。

### 4.9 S10 课程详情、播放与反馈

详情分两块：

**课程本身**

- 时长、主类型、主部位、强度/冲击的用户友好描述；
- 主要动作/姿势提示、需要的设备（仅元数据）；
- 教练和课程说明。

**为什么今天推荐给你**

- 与今天 Training Intent/目标匹配；
- 符合当前能力和限制；
- 若发生 Adapt，说明降级/替换原因；
- 周期只作为众多上下文之一，不宣称课程“黄体期适用”。

播放保持投屏、暂停/继续、字幕与动作提示。完成后反馈建议至少包含：合适、太难、出现不适、没兴趣/其他。选择“不适”时优先显示停止训练和必要安全提示；反馈不自动给出医疗结论。

### 4.10 S25 训练记录

删除压力型 streak、连续中断归零和挑战性比较。替代为：

- 本月已完成次数/时长；
- 训练类型分布；
- “你在按自己的节奏继续”一类非惩罚文案；
- 可选的阶段回顾，不产生排名。

连续天数若保留，只作为私密信息且不用于催促、惩罚或权益门槛。

### 4.11 S26/S28 我的与档案复测

“我的”增加：

- 训练档案；
- 周期事实和预测设置；
- 推荐记录与解释；
- 课程/训练历史；
- 通知设置；
- 隐私、同意、导出和删除。

档案页按“目标与节奏、能力、训练限制、偏好、生命周期”分组，显示最近更新时间。修改采用 preview → 展示影响 → confirm，新版本生效后只 Re-plan 未来。

复测触发采用服务端下发的里程碑配置，不在客户端写死。复测结果显示字段差异，不生成长报告。

### 4.12 S29 课程库

V1 正式筛选：

- 时长；
- Primary Workout Type；
- Primary Body Area；
- 可选的收藏/已完成。

设备可以作为用户主动浏览的元数据，但不读取 User Profile 设备并参与主推荐。难度、场景、空间、协调度只有进入正式 taxonomy/接口后才展示，不能用旧原型枚举占位。

## 5. 老用户迁移

旧 12 题结果不能完整生成新 User Profile。建议：

1. 服务端评估旧答案能映射的字段并标记来源 `LEGACY_MIGRATION`。
2. 登录时只询问缺失的 P0 安全/能力/生命周期字段。
3. 迁移预览显示将保留和需要补充的内容。
4. 用户确认后生成新 Profile v1 和 30 天计划；旧计划保留历史只读。
5. 迁移完成前不基于缺失安全字段自动给新推荐。

## 6. 客户端工程方案

### 6.1 数据与状态

- 通过 OpenAPI 生成 client 和 TypeScript 类型；
- 服务端数据缓存与本地 UI 状态分离；
- Onboarding 草稿、preview id、job id 可恢复；
- mutation 带 Idempotency-Key 与 revision；
- 不在本地重新计算 Fitness Capacity、Hard Filter 或候选排序；
- 字典文案带 taxonomy version，未知枚举显示安全兜底并上报兼容告警；
- 敏感答案不写通用 analytics、崩溃日志或明文本地存储。

### 6.2 弱网/离线

- 浏览缓存的日历和课程元数据可离线只读；
- Onboarding 可安全保存本地加密草稿或逐题服务端保存，策略需通过隐私评审；
- Check-in、周期事实、档案修改需要在线确认，避免离线重复决策；
- 视频下载/缓存如支持，Course Profile/推荐原因仍以决策快照为准；
- 恢复网络后通过 job/preview 状态查询，不盲目重试确认操作。

### 6.3 可访问性与文案

- 文本动态字号、屏幕阅读器标签、足够对比度和触控区域；
- Push/Soft/Warm、计划变化不只用颜色区分；
- 避免“正常/异常、失败、偷懒”等评价身体或行为的词；
- 体重/BMI 不做羞耻化展示；
- 安全提示明确但不过度恐吓；
- 中英文显示可变化，technical value 不随语言变化。

## 7. 埋点与指标

只记录产品行为，不采集不必要的敏感答案明文。

建议事件：

- `onboarding_started/step_saved/submitted/blocked`；
- `profile_summary_viewed/profile_change_previewed/confirmed`；
- `plan_generation_started/completed/failed`；
- `checkin_started/previewed/state_changed/confirmed`；
- `daily_adapt_viewed/accepted/undone`；
- `cycle_fact_previewed/confirmed/corrected`；
- `replan_diff_viewed`；
- `recommendation_reason_viewed`；
- `course_started/completed/feedback_submitted`；
- `no_safe_course_state_viewed`。

属性仅保存枚举、版本、reason code、耗时和匿名 trace；不发送自由文本、具体身体限制或周期日期到通用分析平台。

核心漏斗/质量指标：Onboarding 完成率和 Block 分布、计划生成成功率、Check-in 完成率、状态建议修改率、Adapt 接受/撤销率、解释查看率、无安全课程率、课程完成率与不适反馈率。

## 8. 推送与提醒

- 提醒频率和静默时段由用户控制；
- 文案不在锁屏暴露周期、孕产或身体限制；
- Check-in 提醒只说“看看今天适合怎样活动”；
- 计划变化提醒需要用户打开 APP 查看详情，不在推送中暴露敏感原因；
- 复测里程碑由服务端事件驱动，客户端不自行按天数推算；
- 用户关闭通知不影响 Today 页面正常使用。

## 9. 测试矩阵

### 9.1 关键用户场景

- 新用户普通路径；
- 老用户补充档案；
- L1–L5 边界；
- 膝/腕/下背/肩限制；
- 盆底/腹直肌字段缺失的 Block；
- 产后分支；
- 孕期 V1 Block；
- 不规则周期、实际经期提前/延后；
- Check-in 三个答案 × 用户手动三种状态；
- 无主课程但有 Backup、无任何安全课程；
- Profile 修改与 Check-in 同日发生；
- Re-plan 和 Adapt 同日；
- 预览过期、重复点击、弱网、请求超时和跨时区。

### 9.2 不变量

- Daily Adapt 只改今天；
- Re-plan 不改过去和已完成日期；
- Check-in 不放宽长期安全限制；
- 周期事实不直接等于 Warm；
- PUSH 不自动升级原课程；
- Hard Filter 后无课不返回被排除课程；
- 同一确认操作重试不产生多个 Check-in/计划版本；
- 推荐原因、计划页面和实际播放课程使用同一 decision id/version。

### 9.3 UI 状态

每个改造页面覆盖加载、空、Block、无权限、过期、离线、服务错误、部分成功和撤销失败。至少在常见手机尺寸、大字体、深色模式（如支持）和屏幕阅读器下测试。

## 10. 实施分期

### A. 契约接入与 Onboarding

- 生成 API client、taxonomy 加载和通用异步/错误状态；
- S03–S06 新问卷、档案摘要、Block 和计划生成；
- 老用户迁移。

### B. Today 与 Daily Adapt

- S09/S19/S20 两步确认、主备课程、解释和撤销；
- 周期事实确认与隐私安全埋点。

### C. Calendar 与 Re-plan

- S08/S21 30 天意图、变更 diff、异步任务恢复；
- 同日 Re-plan + Adapt 场景。

### D. 详情、我的和质量完善

- S10、S25、S26、S28、S29；
- 弱网、无障碍、推送、安全和完整自动化回归。

## 11. APP 验收门禁

- 新问卷与后台发布版本一致，分支和 Profile 结果通过合同 fixture；
- 设备问题、旧 12 题、旧目标枚举和长报告已移除；
- Today 不在 Check-in 前推断疲劳，经期不直接显示 Warm；
- Check-in preview/confirm/change/undo 全链可用，首 7 次说明符合配置；
- Soft/Warm 调整使用服务端主备候选并符合顺序；
- 计划、日历、推荐理由和播放课程的版本一致；
- 无安全课程和孕期 Block 有明确、尊重用户且不绕规则的体验；
- 训练档案可查看/修改，修改只影响未来；
- streak 压力型元素已移除；
- 敏感值未进入通用埋点/日志/推送文案；
- 弱网、重复提交、预览过期、跨时区和异步失败通过测试；
- 核心流程完成可访问性和隐私评审。
