# 管理后台开发规划

## 1. 建设目标

管理后台不是普通的课程 CRUD，而是 V1 推荐系统的“配置、审核、模拟、发布、回滚和审计控制面”。后台必须保证产品、课程运营、审核员和技术团队使用同一份标准字典，并能回答：

- 某课程为什么得到这些标签，谁审核、何时生效？
- 某用户为什么在某天得到这门课，哪些候选被什么规则排除？
- 问卷回答如何生成长期训练档案？
- 某次规则发布影响了哪些案例，能否回滚？
- AI 批量任务质量怎样，哪些课程因标签不足无法安全推荐？

当前 B01–B57 的导航、表格、详情抽屉、操作日志和通用权限框架可以复用；课程标签、问卷、排课和用户详情的领域数据需要重构。

## 2. 建议的信息架构

```text
Dashboard
课程中心
  ├─ 课程列表
  ├─ Course Profile 详情/版本
  ├─ AI 打标任务
  ├─ 标签审核队列
  └─ 课程覆盖与缺口
标准与问卷
  ├─ 标准字典
  ├─ Onboarding 版本
  ├─ 分支流程
  └─ User Profile 推导规则
推荐系统
  ├─ Priority / Hard Filter
  ├─ Plan 规则
  ├─ Re-plan 规则
  ├─ Daily Adapt 规则
  ├─ 模拟与回归
  └─ 发布与回滚
用户与计划
  ├─ 用户训练档案
  ├─ 30 天计划/主备候选
  ├─ Check-in / 周期事实
  └─ 推荐决策追踪
审计与权限
  ├─ 敏感数据访问
  ├─ 配置发布记录
  └─ 系统操作日志
```

营销运营标签和敏感训练档案必须分区，避免继续通过 B17 自定义标签承载“多囊/产后/身体限制”等敏感结构化信息。

## 3. 页面改造方案

### 3.1 Dashboard（B01/B02）

保留现有经营/内容数据概览，新增“推荐系统健康度”，但不要把敏感状态做成可下钻的个人排行榜。

建议卡片：

- 已批准 Course Profile 覆盖率；
- 安全字段完整率、unknown 率；
- 待审核/高风险待复核课程数；
- 过去 24 小时 Plan/Re-plan/Adapt 成功率；
- `NO_SAFE_COURSE_MATCH` 用户日比例；
- 四种 Adapt 结果分布：Keep/Adjust/Replace/Rest；
- 当前生效 taxonomy、问卷、四阶段规则版本；
- AI 任务积压、失败率、平均审核时长。

告警卡必须能跳转到过滤后的工作队列，而不是只展示数字。

### 3.2 课程列表与详情（B03/B04）

#### 列表

新增列/筛选：

- Course Profile 状态与版本；
- 主 Workout Type、主 Body Area；
- Overall/Impact Load；
- 经期/产后风险；
- 安全字段完整性；
- AI/人工来源、最后审核人、发布时间；
- taxonomy 兼容状态。

列表中的“经期可用、膝友好、产后适用”二值标签应迁移为风险/负荷摘要，点击后查看理由和证据。

#### 详情 Tab

1. 基本信息：课程媒体、时长、教练、发布状态。
2. Identity：主/次类型、主/次部位、设备元数据。
3. Loads：Overall/Cardio/Muscular/Impact 及局部负荷。
4. Movement：Jump、姿势占比、关键动作。
5. Goals & Risks：目标贡献、经期/产后风险和原因。
6. Evidence：字段级置信度、依据、视频时间片。
7. Review & Versions：AI run、审核差异、版本、生效/回滚记录。
8. Usage：进入候选池/被排除统计，只展示聚合数据。

Course Tagging Demo 中卡路里/MET 移到“实验字段”或删除；`塑形` 不能继续作为 Secondary Workout Type。

### 3.3 标准字典（B06）

每个字典项包含：

- domain、technical key、中文/英文显示文案；
- 数据类型和值域、单位、是否多选；
- 定义、正例、反例、unknown 策略；
- 可用于 User Profile、Course Profile、问卷或规则的范围；
- 依赖/互斥关系；
- 版本、状态、弃用替代项。

已发布字典不可原地改 technical key。发布前校验引用它的问卷、课程档案、规则和客户端最低兼容版本；删除改为弃用。

### 3.4 AI 标签审核（B07）

审核页采用“视频证据 + 字段表单 + 版本差异”三栏布局：

- 左：播放器、帧/字幕时间轴、证据标记；
- 中：A–E 字段、AI 值、置信度、校验告警；
- 右：字典锚点、历史版本、审核意见和批量操作。

支持：

- 点击字段跳转证据片段；
- 逐字段接受/修改/设 unknown；
- 高风险字段双人复核；
- “证据不足/字典不适用/模型误判/输入质量差”等标准原因；
- 保存草稿、提交复核、退回重跑、批准版本；
- 锁定已被另一审核员占用的任务，超时释放；
- 变更 taxonomy 后提示需要重标的字段。

批量接受只能用于低风险且通过门禁的字段，不能覆盖人工已有修改。

### 3.5 Onboarding 版本（B08/B09）

将原来的 12 题配置升级为：

- 15 个主问题与条件分支；
- 问题 technical key、选项 technical value；
- 敏感等级、必填条件、帮助文案；
- 显示条件、跳过条件、Block 动作；
- 回答到 User Profile 字段的映射；
- 冲突优先级和默认 unknown 行为；
- 移动端预览、可达性图和版本差异。

发布前自动检查：

- 无不可达必答题、死循环或无出口分支；
- 所有选项引用正式字典；
- 安全问题都有推导或 Block 结果；
- `PREGNANT` 按 V1 决策进入 Block；
- 已取消设备问题未进入 Profile；
- Fitness Capacity 只输出 L1–L5；
- 所有文案已完成必要语言和隐私审阅。

### 3.6 User Profile 推导（改造 B10）

B10 从“测评结果加权分/长报告”改成“档案推导工作台”：

- 左侧显示模拟回答；
- 中间显示推导后的 Profile JSON/可读摘要；
- 右侧显示每个字段的来源问题、推导规则和冲突裁决；
- 下方显示 Hard Filter 预判、缺字段和是否触发 Block。

支持用固定测试夹具做回归：普通用户、低能力、膝限制、产后、周期不规律、孕期 Block、矛盾回答、缺失回答等。

问卷触发配置从 14/28 天替换为 PDF 默认里程碑，并允许版本化修改；修改不应回写旧记录。

### 3.7 Priority 与 Hard Filter（B11）

全局优先级固定展示为：

```text
Safety > Daily Check-in > Goal/Training Intent > Fitness Capacity
       > Cycle Context > Preference > History
```

Plan 阶段不读取 Daily Check-in，因此页面必须同时显示“全局优先级”和“各阶段实际输入”。Hard Filter 配置需要：

- 规则 technical key、条件、排除原因码；
- 所需 User/Course 字段及 unknown 策略；
- 适用阶段；
- 冲突优先级；
- 样例、影响估算、状态和版本。

安全规则不允许普通运营用户自由拖拽改顺序；必须有高权限、评审和回归门禁。

### 3.8 四阶段规则（B12）

将通用“条件 → 动作”编辑器拆为四个模块：

1. **Priority/Hard Filter**：资格排除与不可放宽约束。
2. **Plan**：30 天结构、每日 Training Intent、候选排序和 Backup A/B/C。
3. **Re-plan**：触发源、未来作用范围、Keep/Adjust/Replace。
4. **Daily Adapt**：Push/Soft/Warm 的顺序动作，只作用今天。

每条规则显示输入字段、输出动作、原因码、解释文案 key、前后依赖和命中统计。编辑器保存草稿不自动生效；发布生成不可变版本。

禁止规则中自由运行脚本。建议使用受限 JSON DSL/决策表，服务端做静态校验与执行步数限制。

### 3.9 模拟与回归（B13）

提供四个模式：

- Plan：输入长期档案和课程池，输出 30 天意图、主备候选；
- Re-plan：输入现有计划与档案/周期事实变化，输出未来差异；
- Daily Adapt：输入当天课程和 Check-in，验证只改今天；
- Combined：同日先 Re-plan 未来，再 Adapt 今天。

结果至少包含：

- 输入版本矩阵；
- 每一步命中规则；
- 每门候选的资格、排序分项和排除原因；
- 原计划与结果的日期级 diff；
- 不变量断言：历史不变、今天/未来作用域正确、Hard Filter 不被绕过；
- 与当前生产版本对比的变化数量。

回归集支持通过/失败门槛、审批意见和结果导出，但导出真实用户样例前需脱敏。

### 3.10 用户列表与详情（B17/B31）

用户详情建议新增：

- 当前 User Training Profile 及版本时间线；
- 字段来源与用户确认状态；
- 30 天计划、每日 Training Intent、Primary/Backup A/B/C；
- Check-in、周期事实和 Re-plan 事件；
- 推荐决策与排除原因；
- 用户反馈和撤销；
- 同意、导出/删除请求和敏感访问记录。

默认页面对敏感字段遮罩；查看需单独权限和填写目的。运营可添加的 CRM 标签仅限营销/服务分类，不能创建“PCOS 友好、产后风险、膝伤”等自由健康标签。

### 3.11 决策与操作日志（B19）

日志分三类：

1. 配置审计：字典、问卷、规则、课程档案的创建、审核、发布、回滚。
2. 推荐追踪：输入版本、候选、排除、决策、解释、耗时和 trace id。
3. 敏感访问：谁在何时以何目的查看/导出了哪些用户范围。

决策详情应支持从一次 APP 推荐跳到对应规则版本和 Course Profile，但历史只读，不能从日志页面直接修改线上数据。

## 4. 核心后台流程

### 4.1 Course Profile 发布

```text
课程内容就绪
  → 创建 AI Job
  → AI_GENERATED 草稿
  → Schema/规则校验
  → 人工审核（高风险双审）
  → APPROVED
  → 发布 Course Profile Version
  → 候选索引更新
```

若课程媒体内容变化、字典不兼容或审核撤回，旧 Profile 保留历史但不再作为新决策候选。

### 4.2 问卷发布

```text
复制当前版本 → 编辑问题/分支/推导 → 自动验证
→ 测试夹具回归 → 移动端预览 → 产品/安全审核
→ 设置生效时间 → 发布 → 监控完成率与 Block 分布
```

已开始的草稿固定问卷版本；发布新版本不能令用户进行中的草稿无法提交。需定义过期兼容或引导迁移策略。

### 4.3 规则发布

```text
草稿 → 静态校验 → 回归集 → 生产影子模拟 → 影响评估
→ 技术/产品/安全审批 → 定时发布 → 监控 → 保留一键回滚
```

发布时记录 taxonomy、Profile Schema 和最低客户端兼容版本。不兼容时阻止发布。

## 5. 权限模型

| 角色 | 典型权限 |
|---|---|
| 课程运营 | 课程元数据、创建任务、查看低敏聚合指标 |
| 课程审核员 | 查看证据、审核普通字段 |
| 安全审核员 | 审核风险/负荷字段、处理高风险双审 |
| 问卷编辑 | 创建问卷草稿、预览和模拟 |
| 规则配置 | 创建规则草稿、运行模拟 |
| 发布审批人 | 发布/回滚问卷、字典或规则，不能单人自审自发 |
| 客服 | 查看必要用户服务信息，敏感字段默认不可见 |
| 审计员 | 只读访问发布、决策和敏感访问日志 |
| 超级管理员 | 管理角色与紧急停用，不用于日常运营 |

高风险标签、Hard Filter、孕期 Block 和敏感导出采用最小权限与双人审批。所有权限检查由服务端执行。

## 6. 前端工程建议

- 以 OpenAPI 生成 TypeScript client，禁止页面手写重复 DTO；
- 字典与 Schema 通过统一数据层加载，表单选项不硬编码；
- 复杂规则编辑器使用结构化 DSL + 可视化表单，不保存任意表达式脚本；
- 所有列表支持 URL 化筛选、分页和可恢复状态；
- 表单草稿有 revision/ETag，冲突时展示字段级 diff；
- 发布、回滚、批量审核为异步任务，显示进度、部分失败和可重试项；
- 证据播放器精确到毫秒区间，并处理视频不可用/字幕缺失；
- unknown、高风险、未审核使用图标+文本，不只依赖颜色；
- 敏感值禁止写入前端埋点、错误上报和浏览器持久缓存。

## 7. 与当前原型的代码改造边界

建议保留：

- App 管理后台路由和 B 编号导航体系；
- 现有 Dashboard、列表、详情、抽屉和日志的视觉组件；
- 通用的状态标签、筛选、分页、权限壳；
- Course Tagging Demo 的分组展示思路。

建议替换：

- B03/B04/B06/B07 的标签字段和状态模型；
- B08–B10 的 12 题、加权分、长报告；
- B11–B13 的单体排课器和 Day1–28 模拟；
- B17 的敏感自由标签；
- B31 的 7/21 天包和旧版“无器械/大基数”输入；
- `data/adminData.ts` 中全部旧枚举与样例。

原型阶段先用一套与 JSON Schema 相同的 fixture 数据，避免第二次数据迁移。

## 8. 非功能要求

- 列表 P95 ≤ 1 s，复杂模拟/批任务异步执行；
- 发布和回滚动作可审计、可重放结果、不可物理删除历史；
- 推荐追踪按 trace id 可在 5 秒内定位；
- 大批量课程审核支持断点续作和任务认领；
- 配置变更前后 diff 可读，技术 key 与展示文案同时显示；
- 无障碍：键盘可操作、焦点清晰、状态不只用颜色；
- 浏览器刷新不丢未提交草稿，敏感草稿除外且需安全存储策略。

## 9. 实施分期

### M1：标准与基础

- 标准字典、问卷版本、User Profile 推导；
- Course Profile 详情/版本；
- 基础 RBAC 和审计框架。

### M2：AI 审核闭环

- AI 任务、审核队列、证据播放器、批准/退回；
- 质量 Dashboard 和课程字段缺口。

### M3：规则控制面

- 四阶段规则、模拟、回归、发布/回滚；
- 版本兼容校验和影子评估。

### M4：用户与决策追踪

- 用户档案、30 天计划、主备候选、Check-in/Re-plan；
- 完整推荐 trace 和敏感访问审计。

## 10. 验收清单

- 后台所有技术值来自正式 taxonomy，无页面私有枚举；
- Course Profile A–E 字段、证据、置信度、审核与版本完整；
- 高风险/unknown 不能通过批量接受绕过审核；
- 问卷分支可视化与移动端执行结果一致；
- User Profile 每个关键字段都可追溯到回答/规则；
- Plan/Re-plan/Adapt 能独立模拟，Combined 顺序正确；
- 回归失败、Schema 不兼容或最低客户端不满足时禁止发布；
- 规则发布、回滚和历史推荐解释使用原版本，无漂移；
- 用户敏感档案与营销标签隔离，查看/导出有权限和审计；
- 任一 `NO_SAFE_COURSE_MATCH` 可定位缺失字段或过滤规则；
- 桌面主流浏览器、键盘操作、错误/空/加载/部分失败状态通过测试。
