# AI 模型项目开发规划

## 1. 项目定位

V1 的 AI 项目只负责把课程视频及其元数据转换为结构化、带证据和置信度的 `Course Profile`。最终用户推荐由确定性规则引擎完成，AI/LLM 不直接决定用户今天练什么，也不能绕过 Hard Filter。

```text
视频/字幕/教练元数据
        ↓
多模态课程理解与结构化打标
        ↓
Schema 校验 + 规则校验 + 置信度门禁
        ↓
人工审核/纠正
        ↓
已批准 Course Profile
        ↓
确定性 Plan / Re-plan / Daily Adapt
```

这样划分的原因是课程打标适合离线、可复核的 AI 提效；涉及周期、限制和产后的个性化决策需要稳定优先级、可重复结果和完整审计。

## 2. 目标与非目标

### 2.1 目标

- 为上线候选课程生成 Course Profile A–E 全量字段；
- 对每个关键字段输出生成依据、时间片证据和置信度；
- 建立 20–30 条金标锚点课程和持续扩充的评测集；
- 支持 300+ 课程批量处理、失败重试、审核和纠正回流；
- 对高风险、低置信度、模型分歧和分布外课程自动转人工；
- 通过模型、Prompt、Schema、字典和输入哈希复现历史结果。

### 2.2 非目标

- 不从视频诊断医学风险或宣称医疗适用性；
- 不预测用户经期或当天身体状态；
- 不直接生成 30 天训练计划或替代规则引擎；
- 不在 V1 自动批准高风险安全字段；
- 不把卡路里/MET、空间需求、协调度、通用难度作为核心交付字段；
- 不支持孕期课程自动匹配，除非后续产品与专业安全评审重新立项。

## 3. AI 输出合同

AI 输出必须符合服务端提供的版本化 JSON Schema；模型不能自由创建标签。输出分为六组：

1. **Identity**：时长、主/次 Workout Type、主/次 Body Area、设备元数据。
2. **Loads**：Overall/Cardio/Muscular/Impact 1–5；膝、腕、下背、肩负荷 1–5。
3. **Movement**：Jump Level/占比、姿势占比、关键动作。
4. **Goal Contribution**：减脂、塑形、健康习惯、产后四项目标贡献 1–5。
5. **Risk**：经期/产后风险等级和结构化原因。
6. **Governance**：字段级 confidence、basis、evidence segments、模型与 Prompt 版本。

为打通问卷中的盆底/腹直肌安全约束，建议在合同评审中增加：

- `pelvic_floor_load: 1..5 | unknown`
- `core_pressure_load: 1..5 | unknown`

如无法定义可靠标签规范，则 AI 必须输出 `unknown`，且相关用户进入人工/无匹配路径。禁止把 unknown 当 1。

### 3.1 字段级证据格式

```json
{
  "field_key": "wrist_bearing",
  "value": 4,
  "confidence": 0.91,
  "basis": ["VISION", "TRANSCRIPT"],
  "evidence_segments": [
    {
      "start_ms": 186000,
      "end_ms": 242000,
      "observation": "持续四点跪姿并多次单臂支撑"
    }
  ]
}
```

证据是审核定位信息，不要求保存模型的隐藏思维过程。只保存可观察事实、输入引用和简短说明。

## 4. 输入与数据准备

### 4.1 输入清单

每条课程建立稳定 `course_id` 和内容哈希，采集：

- 原始/转码视频、帧率、时长、画幅；
- 字幕或 ASR 文本及时间戳；
- 课程名称、教练、官方简介、已有人工分类；
- 章节、动作列表（如有）；
- 历史用户反馈仅用于后续质量分析，不作为首版安全真值。

输入变化必须产生新 `input_hash`，不得复用旧结果。

### 4.2 数据集分层

| 数据集 | 建议规模 | 作用 |
|---|---:|---|
| Gold Anchors | 20–30 课 | 标签说明对齐、少样本示例、发布门禁 |
| Validation | 50–80 课 | Prompt/模型选择与阈值调优 |
| Test | 50–80 课 | 冻结评测，不用于调参 |
| Safety Challenge Set | 30+ 片段/课程 | 高腕承重、高冲击、盆底/核心压力、边界样例 |
| Production Backlog | 300+ 课 | 批量生成与人审 |

集合按类型、部位、时长、教练、镜头风格和安全风险分层抽样。同一课程的剪辑版本不得跨训练/测试集合，避免泄漏。

### 4.3 金标规范

- 由课程专家主标，第二位审核员复核；安全字段分歧需第三方裁决。
- 标注界面直接使用正式字典和 1–5 锚点说明。
- 每个关键标签至少绑定一个时间片证据；没有足够证据使用 unknown。
- 姿势占比允许容差，总和校验为 100%±允许误差。
- 保存标注者、标注指南版本、裁决原因和修订历史。
- 金标不是永久不变；字典语义变化时创建新评测版本，不覆盖旧标签。

## 5. 模型方案

### 5.1 推荐的分层流水线

1. **预处理**：视频探测、音轨提取、ASR、场景/镜头切分、按间隔和动作变化采帧。
2. **候选观察提取**：视觉/姿态模型识别姿势、跳跃、支撑与动作区段；文本模型抽取教练口令、调整提示和器械。
3. **多模态聚合**：模型在完整课程摘要与关键片段上输出符合 Schema 的候选标签。
4. **确定性派生**：姿势占比、时长、数值范围、枚举和互斥条件由代码校验/计算，不交给 LLM 自由发挥。
5. **一致性检查**：例如 `jump_ratio_pct=0` 时 Jump Level 不应高于 1；高腕承重证据缺失时不得高置信度发布。
6. **门禁与路由**：按字段阈值、高风险规则和模型分歧转自动接受候选或人工审核。

首版建议优先使用可替换的成熟多模态模型 + 结构化输出/Prompt 工程，不急于训练大型自有模型。只有在金标量、错误归因和成本数据足够后，再评估小模型微调、蒸馏或专用动作识别器。

### 5.2 模型组合

- ASR：带词级/句级时间戳；
- 视觉采样：通用多模态理解 + 可选姿态/动作检测；
- 结构化聚合：严格 JSON Schema 的多模态/语言模型；
- 规则校验器：纯代码；
- 可选双模型仲裁：只用于高风险或低一致性字段。

模型供应商保持可插拔，不在业务表中写死模型名称。所有调用经统一 Adapter 记录版本、耗时、成本、重试和原始输出位置。

## 6. 置信度与审核策略

不能把模型自己报告的 confidence 直接当真实性概率。建议将最终置信度由以下信号校准：

- 模型/多次运行一致性；
- 视频、字幕、元数据多源一致性；
- 是否存在有效时间片证据；
- 该字段在验证集上的历史精度；
- 是否处于分布外输入；
- 规则校验是否告警。

### 6.1 审核矩阵

| 条件 | 处理 |
|---|---|
| 经期/产后/盆底/核心压力为中高风险 | 100% 人审 |
| 任一安全字段 unknown | 人审或课程不可进入相关候选池 |
| 关键字段低于阈值 | 人审 |
| 模型间分歧超过阈值 | 人审 |
| 新课程类型/新拍摄风格 | 抽样提高至 100%，稳定后再降 |
| 普通字段高置信且通过所有校验 | 可进入快速审核，不能跳过版本发布 |

### 6.2 人审要求

审核员可以逐字段接受、修改或拒绝，必须填写修改原因；播放器能跳转证据片段并同时查看字典锚点。发布高风险标签建议双人复核，审核者不能审批自己批量导入的规则/字典变更。

## 7. 评估体系

### 7.1 字段指标

| 类型 | 指标 |
|---|---|
| 单选分类 | Accuracy、Macro F1、混淆矩阵 |
| 多标签 | Micro/Macro F1、Precision/Recall |
| 1–5 等级 | Exact Accuracy、±1 Accuracy、MAE、Quadratic Weighted Kappa |
| 百分比 | MAE、容差内准确率、总和合法率 |
| 风险 | 各风险级 Recall；高风险漏报单独计数 |
| 证据 | 时间片 IoU/命中率、审核员有效证据率 |
| 结构 | JSON Schema 通过率、一致性校验通过率 |

### 7.2 建议首发门槛

以下是工程初始目标，须由课程与安全负责人在金标集上确认，不代表医学准确性：

- 结构化输出与 Schema 通过率 ≥ 99.5%；
- Primary Workout Type / Body Area 准确率 ≥ 90%；
- 关键负荷等级 ±1 准确率 ≥ 90%；
- 高风险 Recall ≥ 95%，且任何已知高风险漏报必须完成根因修复/人工门禁；
- 关键字段证据有效率 ≥ 90%；
- 上线课程 100% 具有 Approved Course Profile；
- 高风险与低置信字段 100% 完成人工审核。

即使达到指标，也不能取消 Hard Filter 或人工审核门禁。

### 7.3 端到端指标

- AI 建议直接接受率与逐字段修改率；
- 单课平均审核时长；
- 每类字段主要错误原因；
- 每 100 课的重跑/失败量；
- 单课推理成本、P50/P95 处理时长；
- 因标签缺失导致 `NO_SAFE_COURSE_MATCH` 的比例；
- 标签发布后被运营回滚/用户不适反馈关联率。

## 8. MLOps 与可复现性

每次 run 保存：

- `course_id`、`input_hash`、采样策略版本；
- ASR/视觉/聚合模型版本；
- Prompt/模板版本、Schema/Taxonomy 版本；
- 运行参数、原始结构化输出、校验错误；
- 字段级证据与校准后置信度；
- 审核结果、纠正差异、发布的 Course Profile 版本；
- 耗时、Token/计算成本、trace id。

原始视频放对象存储，业务库只保存受控 URI 和哈希。原始模型响应限制访问和留存期；不得在 Prompt 或日志中混入用户敏感数据。

### 8.1 版本关系

```text
Course Content Version
  × Sampling Version
  × Model Version
  × Prompt Version
  × Taxonomy/Schema Version
      → Model Run
      → Review Decision
      → Course Profile Version
```

任一输入合同变化都应明确选择“兼容读取”或“批量重标”，不能静默把旧模型结果标成新字典版本。

## 9. 服务与任务接口

AI Worker 不直接写生效课程档案，建议任务流程：

1. 后台创建 `tagging_job`，锁定模型、Prompt、Schema 与课程集合。
2. Worker 拉取任务并验证 `input_hash`。
3. 分阶段写入 `model_run` 和中间状态，支持按课程重试。
4. Schema/规则校验通过后创建 `AI_GENERATED` Course Profile 草稿。
5. 门禁将草稿路由到审核队列。
6. 审核通过后由 Course Profile 服务执行发布。

任务状态：

```text
QUEUED → PREPROCESSING → INFERENCING → VALIDATING → NEEDS_REVIEW
                                                └→ FAILED
NEEDS_REVIEW → APPROVED → PUBLISHED
             └→ REJECTED / REPROCESS_REQUESTED
```

重试只重跑失败阶段；人工已修改的草稿不能被后台任务静默覆盖。

## 10. 主动学习与迭代

审核纠正可用于下一轮改进，但必须先脱敏、去重并获得数据治理批准。优先采样：

- 模型低置信或模型间分歧课程；
- 新教练、新拍摄方式、新课程类型；
- 高风险字段和安全 Challenge Set；
- 审核频繁修改的字段；
- 与规则引擎“无安全匹配”高度相关的缺失字段。

建议每次模型/Prompt 候选版本都离线跑冻结 Test Set 和上个生产版本的回归集；只有无安全指标回退、成本和时延可接受时才可灰度。

## 11. 监控与告警

- Schema/校验失败率突增；
- unknown、低置信、高风险标签比例漂移；
- 某类型/教练/拍摄风格的人审修改率异常；
- 高风险漏标或发布后紧急回滚；
- 任务积压、超时、重试风暴；
- 模型供应商错误率、限流、成本异常；
- 字典版本与模型输出版本不兼容；
- 新 Course Profile 发布后推荐无课率异常变化。

安全告警应自动暂停对应模型版本/课程集合的发布，不必停止已经批准且版本固定的旧课程档案。

## 12. 项目分期

### A. 规范与金标

- 冻结字段字典、1–5 锚点、unknown 策略和证据规范；
- 完成 20–30 条 Gold Anchors 和审核手册；
- 构建离线评测 runner 与基线报告。

### B. 基线流水线

- 视频预处理、ASR、采帧、多模态结构化输出；
- Schema/一致性校验、任务状态、失败重试；
- 与后台审核最小闭环联调。

### C. 批量打标

- 处理 300+ 课程；
- 按风险与置信度完成人审；
- 输出字段覆盖率、错误分布和课程缺口报告。

### D. 质量优化与上线

- 校准阈值、优化高频错误、建立 Challenge Set；
- 影子运行和新旧标签对比；
- 分批发布 Approved Course Profile；
- 建立监控、暂停、回滚和重标流程。

## 13. 团队职责

| 角色 | 主要责任 |
|---|---|
| 产品/课程负责人 | 字典语义、锚点、冲突裁决、业务验收 |
| 安全/专业审核 | 风险规范、金标裁决、高风险复核 |
| ML/AI 工程 | 模型流水线、评测、校准、MLOps |
| 数据工程 | 视频/字幕资产、数据集、任务与指标管道 |
| 服务端 | Schema、任务 API、Course Profile 发布与权限 |
| 后台前端 | 证据播放器、字段审核、批处理与质量看板 |
| QA | 数据合同、回归集、异常/重试/版本兼容测试 |

## 14. 上线验收

- 金标、验证和测试集合互斥且版本固定；
- 每个正式字段都有定义、值域、正反例和 unknown 策略；
- AI 输出不能创建字典外标签；
- 关键字段都有可定位证据，证据播放器可正常复核；
- 高风险、低置信和 unknown 路由符合审核矩阵；
- 任一 Course Profile 可复现到输入、模型、Prompt、字典和审核记录；
- 300+ 课程批任务支持暂停、续跑、单课重试和不可覆盖人工修改；
- 评测达到冻结门槛，且人审覆盖率和线上课程覆盖率均满足要求；
- 推荐服务只读取 `APPROVED` 版本，不读取 AI 草稿；
- 具备一键暂停模型发布、回滚 Course Profile 和触发重标的运维手册。
