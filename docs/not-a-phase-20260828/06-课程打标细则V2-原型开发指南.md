# 课程打标细则 V2：原型开发指南

适用项目：`cleancircle_prototype`  
适用工具：Cursor  
目标：把《课程打标细则》转换为可评审的 B03/B04/B06/B07 管理后台原型，并明确它与推荐规则、Go API、Motion 的边界。

## 1. 开发边界

本项目只表达页面结构、字段语义、状态和交互，不定义生产数据库，也不在前端计算正式安全结论。

统一链路：

```text
Motion 观察事实
  → Go 规则计算 Course Profile V2 草稿
  → B07 逐字段复核
  → B04 形成不可变 Profile 版本
  → APPROVED 后供推荐规则读取
```

必须遵守：

- Motion 只负责“看到了什么”，例如动作、比例、次数、持续时间和置信度。
- Go 负责按固定规则版本推导标签和经期/产后适用性。
- 原型不得暗示 AI 能给出医学判断。
- `UNKNOWN`、证据不足和规则冲突必须进入 `REVIEW`，不能显示成低风险或允许。
- V2 上线前保留 V1 对照，不直接删除当前推荐仍在使用的字段。

## 2. 现有实现入口

优先在以下文件上修改，不新建第二套页面体系：

| 文件 | 作用 | V2 改造 |
|---|---|---|
| `src/views/CourseTaggingDemoView.tsx` | 课程画像与打标演示 | 替换旧字段、增加规则命中和证据展示 |
| `src/data/v1Overlay.ts` | B03/B04/B06/B07 与推荐规则原型 | 更新列表、详情、审核、规则依赖 |
| `src/views/ScreensView.tsx` | 原型入口 | 保持现有入口，必要时更新说明 |
| `src/data/mobile/screens-b.ts` | SOFT/WARM 展示 | 更新旧 Impact/Jump 表达 |

当前演示中的 `secondaryType`、`secondaryBodyAreas`、`cardio`、`muscle`、`impact`、数值型局部负荷和“低/中/高风险”均属于 V1 展示，不应继续作为 V2 正式字段。

## 3. 原型领域模型

建议先把 `Course` 演示类型拆成以下结构，避免继续把全部字段放在一个扁平对象中：

```ts
type ReviewStatus =
  | "DRAFT"
  | "AI_GENERATED"
  | "NEEDS_REVIEW"
  | "APPROVED"
  | "REJECTED"
  | "SUPERSEDED";

type TernaryEligibility = "ALLOWED" | "FORBIDDEN" | "REVIEW";
type ObservationLevel = "NONE" | "SOME" | "FREQUENT" | "UNKNOWN";
type LocalLoadLevel = "LOW" | "MEDIUM" | "HIGH" | "UNKNOWN";
type InversionState = "NONE" | "PRESENT" | "UNKNOWN";

interface CourseProfileV2 {
  schema_version: "course_profile_v2";
  tagging_rule_version: string;
  eligibility_rule_version: string;
  identity: {
    content_type:
      | "WORKOUT"
      | "RECOVERY"
      | "REST_REFLECTION"
      | "EDUCATION_TALK"
      | "ASSESSMENT_TEST";
    primary_workout_type?:
      | "WALKING"
      | "CARDIO"
      | "HIIT"
      | "STRENGTH"
      | "PILATES"
      | "MOBILITY"
      | "STRETCH"
      | "RECOVERY"
      | "POSTPARTUM_RECOVERY";
    primary_body_area?:
      | "FULL_BODY"
      | "UPPER_BODY"
      | "LOWER_BODY"
      | "CORE"
      | "GLUTES"
      | "LEGS"
      | "ARMS"
      | "BACK_SHOULDER";
    duration_sec: number;
  };
  intensity: {
    overall: 1 | 2 | 3 | 4 | 5 | null;
    met?: number | null;
    met_source?: "CURATED_LOOKUP" | "CALORIE_NORMALIZED" | "MANUAL" | "UNKNOWN";
    calorie_type?: "GROSS" | "ACTIVE" | "UNKNOWN";
    status: "DERIVED" | "CONFIRMED" | "REVIEW";
  };
  action_exposure: {
    running: ObservationLevel;
    jump: ObservationLevel;
    wrist_bearing: ObservationLevel;
  };
  local_load: {
    knee: LocalLoadLevel;
    ankle: LocalLoadLevel;
    lower_back: LocalLoadLevel;
    shoulder: LocalLoadLevel;
  };
  goal_contributions: {
    fat_loss: 1 | 2 | 3 | 4 | 5;
    body_shaping: 1 | 2 | 3 | 4 | 5;
    healthy_living: 1 | 2 | 3 | 4 | 5;
    postpartum_recovery: 1 | 2 | 3 | 4 | 5;
  };
  eligibility: {
    menstrual: TernaryEligibility;
    postpartum: TernaryEligibility;
    inversion: InversionState;
    triggered_rule_ids: string[];
  };
  governance: {
    review_status: ReviewStatus;
    motion_job_id?: string;
    model_version?: string;
    taxonomy_version: string;
  };
}
```

`UNKNOWN` 是系统状态，不是业务标签的第四档；它用于阻止自动发布并进入人工复核。

## 4. 页面改造

### 4.1 B03 课程列表

列表字段：

- 课程 ID、标题；
- Content Type；
- Primary Workout Type；
- Primary Body Area；
- Overall Intensity；
- Menstrual / Postpartum Eligibility；
- V1/V2 Profile 版本；
- 完整度、审核状态、最后更新时间。

新增筛选：

- `FORBIDDEN`、`REVIEW`、安全字段缺失；
- `POSTPARTUM_RECOVERY`；
- 低置信度、规则冲突；
- 仅有 V1、已生成 V2、V1/V2 结果不一致。

不要在列表继续用单个 `Impact` 数字概括动作风险；改为显示 `Running / Jump / Ankle` 摘要。

### 4.2 B04 Course Profile 详情

页签建议：

1. `Identity`：内容类型、主训练类型、主部位、时长。
2. `Intensity`：MET、数据来源、热量口径、Overall。
3. `Movement & Loads`：三项动作暴露、四项局部负荷、原始指标。
4. `Goals`：四项目标贡献及查表规则来源。
5. `Eligibility`：经期、产后、Inversion、命中规则与覆盖关系。
6. `Evidence & Versions`：时间片、置信度、审核记录、版本 diff。

每个正式标签组件至少展示：

```text
字段值 → 原始指标 → 命中规则 → 证据片段 → 来源/版本 → 审核状态
```

### 4.3 B06 Taxonomy 与规则版本

新增三个版本对象的可视化：

- `course_profile_v2`：字段和值域；
- `course_tagging_rules_v2`：强度、动作暴露、局部负荷规则；
- `course_eligibility_rules_v2`：经期、产后和白名单规则。

已发布 technical key 不允许原地改语义。`BACK_SHOULDER`、Recovery 的双重含义和 Postpartum Recovery 白名单在需求冻结前显示为待决项。

### 4.4 B07 字段证据复核

使用“播放器 + 字段表单 + 规则解释”三栏布局：

- 左侧：视频、时间轴、证据片段；
- 中间：正式字段、AI/规则建议、人工裁决；
- 右侧：原始指标、阈值、命中规则、版本和历史差异。

支持接受、修改、设为 Unknown、驳回和提交终审。修改或驳回必须填写标准原因码。

`POSTPARTUM_RECOVERY` 不能因为类型命中就显示为自动允许；必须展示它覆盖了哪些普通禁用规则，并明确需要健康运营终审。

### 4.5 V1/V2 对照页

迁移期增加只读 diff：

| V1 | V2 | 表达 |
|---|---|---|
| Impact 4 | Running Some / Jump Frequent / Ankle High | 非一对一转换 |
| Cardio 4 | Cardio + Overall 4 | 仅对照，不自动等价 |
| Muscular 3 | Strength + Knee Medium | 仅对照，不自动等价 |
| 经期风险 High | Menstrual Forbidden | 展示命中规则 |

不存在可靠映射时显示“不可自动迁移”，不要伪造 V2 值。

## 5. 推荐规则原型同步

B12/B13 必须同时更新，否则课程页和推荐页会使用两套语义：

- Hard Filter 读取 Eligibility、用户限制与局部负荷；
- Fitness Capacity 读取 Overall，并结合 Workout Type；
- SOFT/WARM 优先降低 Overall、Running、Jump 和相关局部负荷；
- 保留 Primary Workout Type、Primary Body Area 和目标意图；
- 无安全候选时返回 Rest/No Match；
- 迁移期展示 `profile_schema_version` 和规则版本。

不要用 `Overall` 单独反推旧 Cardio/Muscular/Impact。

## 6. 演示数据要求

至少准备以下课程：

1. Walking：Running Some、Jump None、Overall 2–3。
2. HIIT：Jump Frequent、Knee/Ankle High、经期与产后 Forbidden。
3. Pilates Core：用于验证 Core 与经期/产后规则。
4. Strength：用于验证膝、下背、肩局部负荷。
5. Recovery：用于验证 Content Type/Workout Type 组合。
6. Postpartum Recovery：用于验证白名单、覆盖规则和双审。
7. Unknown：画面不足或规则冲突，Eligibility 必须为 Review。

所有演示课程都应有原始指标、规则 ID 和至少一个可点击证据片段。

## 7. 验收清单

- 页面不再把 V1 字段当作 V2 正式字段。
- B03/B04/B06/B07 字段和 technical key 完全一致。
- Unknown 不显示为 Allowed 或 Low。
- Eligibility 能解释具体命中的规则。
- 所有修改均形成版本差异，不覆盖历史展示。
- APPROVED 与未批准 Profile 的视觉状态清晰。
- 推荐模拟能够显示 V1/V2 输入版本和结果差异。
- 运行 `npm run lint` 和 `npm run build`。
