## 2. 三项未决（产品拍板前不得当最终合同）

### P1 · `BACK_SHOULDER` 命名

- **问题**：主部位是保留 `BACK_SHOULDER`，还是拆成 `BACK` / `SHOULDER`，或改名。
- **可先做**：枚举里保留当前 key；UI 可显示「待决」。
- **禁止**：在 OpenAPI / DB check constraint / 推荐匹配里把该 key 写成不可迁移的硬编码分支（可配置表除外）。
- **拍板后动作**：改 taxonomy 版本 → Go Schema → Web 文案 → App 展示文案；发新版本，禁止原地改语义。

### P2 · Recovery 的 Content Type / Workout Type 双重含义

- **问题**：`content_type=RECOVERY` 与 `primary_workout_type=RECOVERY` 是否并存、分别表示什么；与 `STRETCH` / `REST_REFLECTION` 如何区分。
- **可先做**：两字段都落库；校验只做「值域合法」，不做「两者必须相等/互斥」的强约束。
- **禁止**：用其中一个字段反推另一个；在 Hard Filter 里仅因 `RECOVERY` 字符串放行安全限制。
- **拍板后动作**：补一张对照表进 taxonomy，并加 validator + 后台说明文案。

### P3 · Postpartum Recovery 白名单覆盖范围（影响最大）

- **问题**：`POSTPARTUM_RECOVERY` 可覆盖哪些普通禁用规则、哪些绝不可覆盖、是否始终双审。
- **产品已明确底线**：类型命中 ≠ 自动 `ALLOWED`；须健康运营终审。
- **冻结前强制行为（Go）**：
  - 白名单命中时，`postpartum` **输出 `REVIEW`**（不是 `ALLOWED`）；
  - 可记录建议覆盖的 `triggered_rule_ids` / 预留 `overridden_rule_ids`，但不得自动清掉 FORBIDDEN；
  - Hard Filter 对 `REVIEW` / `UNKNOWN` fail closed。
- **冻结前强制行为（Web）**：展示「覆盖候选 + 仍需终审」，禁止一键批量批准为 Allowed。
- **拍板后动作**：实现显式覆盖表与回归用例，再允许受控的终审通过路径。

## 3. 推荐开发顺序（Gate）

```text
G0  产品拍板 P1/P2/P3（可并行开工 G1，但不能关闭 Gate）
  ↓
G1  Go：V2 Schema + Motion 事实接入 + 打标规则（不含最终白名单覆盖）
  ↓
G2  Web：结构化 Profile / B07 三栏复核 / 版本 diff（只调 Go）
  ↓
G3  Go：Eligibility 规则表 + Hard Filter 投影（白名单未冻结则保持 REVIEW）
  ↓
G4  回归夹具（含 HIIT FORBIDDEN、Unknown REVIEW、Postpartum 双审）
  ↓
G5  App 接入 APPROVED 投影（最后）
```

### 可并行

| 可并行 | 说明 |
|---|---|
| Motion 原始指标/证据 | 不输出 Eligibility |
| Web 页面骨架与播放器 | mock Go 合同，不本地算规则 |
| Prototype 评审 | 已完成 V2 待决展示 |
| App 通用错误/加载 | 不绑死 V2 枚举文案 |

### 不可抢跑

| 禁止抢跑 | 原因 |
|---|---|
| 把产后白名单写成自动 ALLOWED | 安全合同未冻结 |
| App 自行推导经期/产后结论 | 结论只在 Go |
| Web 直连 Motion 算标签 | 违反边界 |
| 用 Overall 反推旧 Cardio/Impact | V2 明确禁止 |
| 已发布 technical key 原地改语义 | 必须发新版本 |

## 5. 产品需补充的最小资料（拍板用）

不需要补接口/DB 设计。只要三份结论：

1. **部位枚举终稿**（含是否保留 `BACK_SHOULDER`）
2. **Recovery 对照表**（Content Type vs Workout Type vs STRETCH / REST_REFLECTION）
3. **产后白名单覆盖表**（可覆盖 rule_id / 不可覆盖 rule_id / 是否始终双审）

拍板后：更新本文件状态 → 升 `taxonomy` / `eligibility_rules` 版本 → 各端跟版本，不原地改 key 语义。
